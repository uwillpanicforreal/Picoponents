# Picoponents
An ECS system for Picotron

## AI disclaimer
For the sake of transparency, let me confirm. I did use claude code as part of the deveopment of this system.

In this particular project, which is largely a learning exercise for myself, I'm using Claude to develop a lesson plan for myself around developing an efficient ECS. At no point was or will Claude ever be permitted to write code directly, though I may use it to generate small snippets that I paraphrase. It may also be used for debugging, just to track down bugs without too much fuss. All that and some basic code reviews. If you have ethical concerns about AI and its use, I do too. This is a use case I personally feel is a "good" use of AI, but if you don't, no judgement. Figured I'd make sure you at least get the chance to make that choice yourself.

It's very important to me that the exact extent of AI use in my projects is very transparent. If you feel unclear about how it is used in this project, or you feel I've used it outside the scope outlined hear, please let me know so I can update this section.

## Why?
I've always bounced pretty hard off of game dev because pretty much every engine I've found works in a way that doesn't scratch that factorio itch that I want coding to scratch. I also find that these engines are very feature-rich and, therefor, have very cluttered UIs that give my audhd brain the ouchies. I am also a huge advocate for making your own tools. It's the same reason I run neovim instead of an IDE both professionally and in my hobby coding. I've obsessively tweaked my own custom config there for years, an amount that is probably comparable to the time I've spent on actual production code. Maybe more. Maybe I have a problem. Maybe you have a problem. Shut up.

But yeah, I hate using game engines for the same reason I hate using IDEs. Even the lightest one is heavier than I like. I want exactly the features I use, I want to understand exactly how those features work, and I want my ui to be nothing but a text editor.

## Is this for me?
What? No. No one should use this. At least not now, I mean fuck, as I'm writing this all I have in this repo is some basic benchmark scripts. One day it might be polished enough for people who aren't me to use, but probably this will never be something good for wide use.

## Roadmap
First priority is making something that pushes Picotron to the absolute max in terms of performance. Eventually I'll include some benchmarks for entity count. When that's nice and high, I'll actually start making a game with it maybe.
After that, any tool that I add for my own games will become part of an engine that will live here. These features are out of scope for now, but eventually I may add a 3d rendering engine, a physics engine, and some form of voxel-based world generation. Probably that last one first. I have some ideas for an isometric survival game with a 3d world to explore, but we'll get there when we get there.
